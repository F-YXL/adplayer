# 版本号规范

采用语义化版本 `主版本.次版本.修订号`，例如 `1.1.0`。

| 位数 | 何时 +1 | 例子 |
|---|---|---|
| 修订号（第 3 位） | 修 bug、优化体验、调整文案 | 1.0.0 → 1.0.1 |
| 次版本（第 2 位） | 新增功能（向下兼容） | 1.0.3 → 1.1.0 |
| 主版本（第 1 位） | 架构级改动、不兼容变更 | 1.x → 2.0.0 |

规则：

1. 修订号进位时次版本、主版本不变；次版本进位时修订号归零。
2. `android:versionCode` 必须单调递增。历史版本用的是简单递增编号（1.1.0 = 100），后续版本在此基础上 +1 即可（101、102…），**永远不能比上一版小**，否则系统会拒绝覆盖安装。
3. 每次发版必须：改 `src/AndroidManifest.xml` 的 `android:versionName` 与 `android:versionCode`、更新 CHANGELOG、打 `vX.Y.Z` tag 指向发布提交。
4. 页面上的版本号（HttpUploadServer 里的 `vX.Y.Z`）必须与 versionName 一致，方便用户确认没有缓存。
5. **构建产物不入库**（`.gitignore` 已排除 `*.apk`）。如需分发二进制，只挂 GitHub Release，并在 Release 里附 `SHA256SUMS` 与签名证书指纹；当前仓库只发布源码。
6. 旧的 v1~v32 编号已作废，不再使用。

首个公开版本：`1.1.0`（versionCode 100）；1.2.0 = versionCode 101，1.2.1 = 102。
